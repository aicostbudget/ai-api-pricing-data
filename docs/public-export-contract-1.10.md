# Public downloadable pricing contract 1.10.0

Website JSON/full CSV and HF downloadable JSON/prices.csv share logical records keyed by provider_id+model_id and the same pricing, tier, component, access/binding and provenance meanings. HF train.csv is a reduced Viewer projection; it must preserve the keyset and scalar meanings but intentionally omits large serialized fields. Metadata may add HF features and last_verified_at aliases; notes may use an empty string versus null. These format-specific differences are not pricing parity exceptions.

1.8.0 introduced structured components and modality/transport/usage conditions. Website 1.9.0 documented access/binding as additive; HF already exported those fields while its version label lagged at 1.8.0. Current 1.10.0 explicitly adds the generic optional pricing_components[].condition.promotion contract. This is additive: no existing CSV columns are renamed/reordered; pricing_components_json carries the identical nested object. A consumer that rejects unknown nested properties must opt into 1.10.0. Historical 1.8/1.9 releases remain pinned to their original version and bytes; release reconstruction selects the version from the committed mirror, never relabels history.

promotion: {label: string, discount_percent: number, duration_text: string, price_basis: "promotional", list_charges: [{charge_id, component, modality, unit, amount: decimal string}]}. Current charge amount remains on the parent component; list_charges retain original/list amounts by charge identity. Currency, provenance/source_refs/source_urls/verification timestamps and effective interval remain on the component/record. No absolute end date is derived from duration_text; unknown effective_until remains null. Absence of promotion means no promotion is asserted, not a zero discount. CSV quotes/escapes the full JSON via the existing CSV encoder; nullable scalar fields remain empty cells, structured null values remain JSON null.

Dates: model release, provider price effective_from, observation/verification, and generation timestamps are distinct. Legacy scalar rates are compatibility/default text/short-context projections, not replacements for tiered or image output charges. Unresolved lifecycle-only rows are excluded by existing public/default safety policy; downloads cannot assert a certain lifecycle or shutdown date for them. Saved historical IDs are not remapped.

Existing format mappings are explicit and price-independent: HF adds released_at from the projection. Website notes may include adapter warnings, temporal pricing reminders or modality support descriptions, whereas HF notes retain provider billing prose; all machine-readable charges/conditions/provenance remain equal. The two OpenAI legacy fallback rows gpt-5.3-codex/gpt-5.4-nano preserve Website editorial status versus HF projection status; lifecycle eligibility remains in the shared model-selection/access contract. DeepSeek v4-flash aliases now retain the existing time_pricing summary through the Website legacy fallback, matching the full HF schedule. Three Gemini 3.8 mixed-unit rows have Website pricing_unit=null versus HF scalar compatibility label "1M tokens"; component.unit is authoritative. These narrowly enumerated historical mappings are regression-checked, not blanket exceptions for new models or pricing fields.
